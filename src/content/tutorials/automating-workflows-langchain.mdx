## Why Agents for Workflows

Deterministic tools (cron, Zapier, Airflow) are perfect for predictable steps. But real business workflows hit **unstructured** inputs — emails, PDFs, chat — where the hard part is *understanding* the content. That's where an LLM agent earns its place: it reads the mess, extracts structure, and then hands off to ordinary, reliable code.

We'll build an **invoice-processing** workflow: extract the fields from raw invoice text, then route them to downstream systems. Crucially, we'll **measure extraction accuracy** on a labeled set first — because an extractor you haven't measured is one you can't trust with money.

## Step 1: Define the Structured Output

The reliability win is forcing extraction into a typed schema instead of free-form text. Define the shape with Pydantic.

```python
from pydantic import BaseModel, Field

class Invoice(BaseModel):
    vendor: str = Field(description="The company that issued the invoice.")
    invoice_number: str
    total: float = Field(description="The total amount due, as a number.")
    due_date: str = Field(description="Due date in YYYY-MM-DD format.")
```

## Step 2: Extract With a Typed Model

`with_structured_output` makes the model return an `Invoice` object directly — no JSON parsing, no regex.

```python
from langchain.chat_models import init_chat_model

llm = init_chat_model("openai:gpt-4o")
extractor = llm.with_structured_output(Invoice)

def extract_invoice(text: str) -> Invoice:
    return extractor.invoke(f"Extract the invoice fields from:\n\n{text}")
```

Try it:

```python
sample = """
INVOICE #2025-0142
From: Acme Cloud Services
Date: March 15, 2025  Due: April 15, 2025
GPU Compute (100 hrs) .... $4,500.00
Storage (2TB) ........... $150.00
Total Due: $5,118.12
"""
inv = extract_invoice(sample)
print(inv.vendor, inv.total, inv.due_date)
# Acme Cloud Services 5118.12 2025-04-15
```

## Step 3: Measure Extraction Accuracy

Before wiring this into anything, find out how often it's *right*. Build a small labeled set — a few invoices paired with their known-correct fields — and score field by field. For money, the `total` and `vendor` fields are what matter most.

```python
EVAL = [
    {"text": sample, "vendor": "Acme Cloud Services", "total": 5118.12, "due_date": "2025-04-15"},
    {"text": "Bill from Globex Inc — Invoice 88. Amount due $1,200.00 by 2025-05-01.",
     "vendor": "Globex Inc", "total": 1200.00, "due_date": "2025-05-01"},
    {"text": "Initech statement #A-7. Pay $940.50 no later than June 3, 2025.",
     "vendor": "Initech", "total": 940.50, "due_date": "2025-06-03"},
]

def score():
    field_hits = {"vendor": 0, "total": 0, "due_date": 0}
    for case in EVAL:
        inv = extract_invoice(case["text"])
        field_hits["vendor"]   += inv.vendor.lower() == case["vendor"].lower()
        field_hits["total"]    += abs(inv.total - case["total"]) < 0.01
        field_hits["due_date"] += inv.due_date == case["due_date"]
    n = len(EVAL)
    for field, hits in field_hits.items():
        print(f"{field:10} {hits}/{n} = {hits / n:.0%}")

score()
```

A representative run:

```text
vendor     3/3 = 100%
total      3/3 = 100%
due_date   2/3 = 67%
```

Now you know exactly where it's weak (date formats, here) — so you can tighten the prompt or add a normalizer *before* this ever touches an accounting system. That's the difference between "the demo worked" and "we measured 100% on totals across our test set."

## Step 4: Orchestrate the Full Workflow

With extraction trusted, wrap it and the downstream actions as tools and let `create_agent` run the workflow end to end.

```python
from langchain.agents import create_agent
from langchain.tools import tool

@tool
def extract(text: str) -> str:
    """Extract structured fields from raw invoice text."""
    return extract_invoice(text).model_dump_json()

@tool
def save_invoice(invoice_json: str) -> str:
    """Persist an extracted invoice (JSON) to the database."""
    inv = Invoice.model_validate_json(invoice_json)
    # ...real DB write here...
    return f"Saved invoice {inv.invoice_number} from {inv.vendor}."

@tool
def notify(message: str) -> str:
    """Send a Slack notification summarizing a processed invoice."""
    # ...real Slack call here...
    return f"Notified: {message}"

agent = create_agent(
    model="openai:gpt-4o",
    tools=[extract, save_invoice, notify],
    system_prompt=(
        "You process invoices. Extract the fields, save them, then send a one-line "
        "notification with the vendor and total. Flag any total over $10,000 for human review."
    ),
)

result = agent.invoke({"messages": [{"role": "user", "content": f"Process this:\n{sample}"}]})
print(result["messages"][-1].content)
```

## Production Patterns

A few additions turn this into something you can run unattended:

```python
# 1. Human-in-the-loop gate for high-value invoices
@tool
def request_approval(summary: str) -> str:
    """Queue an invoice for human approval; returns 'approved' or 'rejected'."""
    # send to an approval queue and wait...
    return "approved"

# 2. Retry with backoff around the whole run
import time

def process_with_retry(text: str, retries: int = 3) -> str:
    for attempt in range(retries):
        try:
            r = agent.invoke({"messages": [{"role": "user", "content": text}]})
            return r["messages"][-1].content
        except Exception:
            if attempt == retries - 1:
                raise
            time.sleep(2 ** attempt)
```

Round it out with logging every extraction (your eval set grows from real traffic) and re-running `score()` on a schedule to catch drift.

## Putting a Number on the Value

Once you've *measured* extraction quality, the ROI case writes itself. Plug your own figures into the same shape:

| Metric | Manual | Automated | Source |
|---|---|---|---|
| Time per invoice | 15 min | ~30 sec | wall-clock |
| Extraction accuracy (total) | — | measure it (`score()`) | your eval set |
| Invoices/day per person | ~30 | hundreds | throughput |

The point: lead with the accuracy number you actually measured, not a number you hope for.

## Common Pitfalls

| Mistake | Why it hurts | Fix |
|---|---|---|
| Free-form text extraction | Brittle parsing; silent field errors | `with_structured_output(PydanticModel)` |
| Shipping before measuring | You can't trust money fields you never tested | Score a labeled set field by field |
| `AgentExecutor` from old guides | Pre-1.0 API | Use `create_agent` |
| No human gate on large amounts | One bad extraction = a costly mistake | Route high totals to `request_approval` |
